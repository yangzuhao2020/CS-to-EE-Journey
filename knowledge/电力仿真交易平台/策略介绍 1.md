## 2.1 powerplant_energy_heuristic_flexable
考虑最低出力、启停状态、启动成本、爬坡、未来价格和热电联产。
	将一台机组拆成两条报价。第一部分属于最低稳定出力，然后第二部分属于灵活出力。
### 2.1.1 灵活出力定价
灵活出力通常按边际成本报价。增加出力会增加总燃料与碳排放成本；但在当前实现中，单位电量的边际成本不随出力变化。
### 2.1.2 最低出力怎么定价
最低出力的价格取决于机组当前是“运行”还是“停机”。
- 停机：如果要让机组启动，除了燃料成本，还要支付启动成本。$$p_{\text{inflex}} = C_{\text{marginal}} + \frac{C_{\text{start}}}{T \times q_{\text{inflex}}}$$其中： $$T=\max(\text{avg\_op\_time},\text{min\_operating\_time})$$
$$\text{avg\_op\_time} = \frac{\text{累计出力大于 0 的时段数}}{\text{截至当前的总时段数}}$$
	注意：名称虽为 op_time，但不是平均连续运行小时数。
	q_inflex 是经过可用率、已有出力、其他市场承诺和爬坡修正后的最低报价量。
	所以，边际成本 + 启动费用=最低出力报价。($C_{start}$启动成本可能为0)

- 运行：如果现在关闭机组，将来再启动，还会产生启动成本。所以机组可能愿意让最低出力暂时少赚一点，甚至亏一点，也不愿意关闭。$$p_{\text{inflex}} = C_{\text{flex}}^* - \text{避免重启带来的价值} - \text{供热相关的报价下调（成本分摊）}$$
	当未来 12 小时累计预期收益**非负**、且当前预测电价低于边际成本时，代码会将 $C_{\text{flex}}^{*}$ 设为 0。
- 未来价格预测
	该策略默认读取从当前时点开始、长度约 12 小时的 `EOM` 价格预测，并计算累计预期收益：
$$
R_t=\sum_{\tau=t}^{t+12h}\left(p_{\tau}^{\text{forecast}}-C_{\text{marginal}}\right)$$
  当 $R_t \ge 0$，且当前小时预测价格 $p_t^{\text{forecast}} < C_{\text{marginal}}$ 时，代码会将 $C_{\text{flex}}^{*}$ 设为 0。

```mermaid
flowchart LR
  A["demand_df.csv<br/>未来每个时段的负荷"] --> B["加载并按仿真步长重采样"]
  B --> C["DemandForecaster.demand<br/>demand = -abs(demand_df[unit])"]
  C --> D["calculate_sum_demand()<br/>取绝对值并汇总所有非弹性需求"]
  D --> E["calculate_naive_price()<br/>与同一时段的可用供给比较"]
  E --> F["price['EOM'][t]<br/>边际机组成本"]
```

### 2.1.3 额外的约束
在生成两条报价之前，代码还会检查：
- 机组可用率；
- 最大功率和最小功率；
- 当前已发功率；
- 已经在其他市场承诺的容量；
- 爬坡速度；
- 最小开机时间；
- 最小停机时间；
- 当前连续运行或停机时长；
- 热电联产的供热任务。
例如机组当前出力为300 MW，最大向上爬坡速度为每小时200 MW，那么下一小时最多只能达到：
$$300+200=500 MW$$
只有加入真实的启动成本、爬坡速度和最小启停时间后，启发式策略与朴素策略才会明显不同。

为什么不是最优？
	它没有联合求解未来24小时的全局利润最大化问题，也不能保证得到理论最优报价。
朴素策略只看“现在发一度电需要多少钱”；启发式策略还会考虑“现在停机后面是否要重新启动，以及未来几个小时是否值得继续运行”。

## 2.2 demand_energy_heuristic_elastic
把一个负荷拆成多档需求报价。电价低时多用电，电价高时少用电。它适合电动汽车充电、储能充电、可推迟工业任务，以及我们之前提到的“算电协同”——核心服务器负荷必须运行，而部分AI训练任务可以等电价降低后再执行。

|负荷等级|数量|最高愿付价格|
|---|--:|--:|
|核心负荷|5 MW|100 EUR/MWh|
|普通负荷|5 MW|75 EUR/MWh|
|可调负荷|5 MW|50 EUR/MWh|
|可推迟负荷|5 MW|25 EUR/MWh|
**最重要的部分：价格很高也要买**
**较重要的部分：价格合适才买**
**可推迟的部分：只有价格很低才买**

{
    "name": "demand_elastic",
    "technology": "elastic_demand",
    "bidding_EOM": "demand_energy_heuristic_elastic",
    "max_power": 20, # 最大可消费功率
    "min_power": 0,
    "unit_operator": "elastic_de",
    "elasticity": -0.05, # 需求价格弹性
    "elasticity_model": "isoelastic",  # 使用等弹性需求曲线
    "max_price": 3000, # 最高愿付价格
    "num_bids": 10 # 把需求曲线拆成10档报价
}

其中的弹性 `−0.05` 是什么意思呢？
$$ E = \frac{\text{需求量变化百分比}}{\text{价格变化百分比}} \quad E = -0.05$$
大致表示：
> 电价上涨1%，需求量下降0.05%。负号表示价格上涨时，用电量下降。

### 2.2.1 等弹性需求曲线
ASSUME 使用：
$$ Q(P) = Q_{\max} P^{E} $$
因为市场最高报价是3000，所以首先计算：
$$
Q_{\text{first}} = Q_{\max} P_{\max}^{E}
$$
代入：
$$
Q_{\text{first}} = 20 \times 3000^{-0.05} \approx 13.402\ \text{MW}
$$
这表示：
> 即使电价达到3000 EUR/MWh，这个负荷仍然希望购买约13.402 MW。

因此第一档报价为：
```
{
    "volume": -13.402,
    "price": 3000
}
```
剩余可调负荷为：20−13.402=6.598 MW
`num_bids=10`，除第一档外还需要生成9档，因此每档数量为：
$$
\frac{6.598}{9} \approx 0.733\ \text{MW}
$$

使用公式：

P = \left( \frac{Q}{Q_{\max}} \right)^{1/E}
$$
已知：

- 第二档累计需求 Q = 14.1352296 MW

最高愿付价格≥市场出清价格；

## 2.3 storage_energy_heuristic_flexable
也就是储能参与电能量市场的启发式报价策略。

原因是它正好把已经学过的内容连接起来：
- 充电时，储能是需求方，报价量为负数；
- 放电时，储能是供给方，报价量为正数；
- 根据预测电价决定充电还是放电；
- 受到 SOC、容量、充放电功率和效率限制。

### 2.3.1 基本规则：
```
当前预测电价 < 未来平均电价
→ 现在便宜
→ 充电买电

当前预测电价 > 未来平均电价
→ 现在较贵
→ 放电卖电
```

|           参数           |    数值    |   含义   |
| :--------------------: | :------: | :----: |
|   `max_power_charge`   | 1000 MW  | 最大充电功率 |
| `max_power_discharge`  |  992 MW  | 最大放电功率 |
|  `efficiency_charge`   |   0.86   |  充电效率  |
| `efficiency_discharge` |   0.90   |  放电效率  |
|       `min_soc`        |    0     | 最低荷电状态 |
|       `max_soc`        |    1     | 最高荷电状态 |
|       `capacity`       | 6076 MWh | 最大储能容量 |
### 2.3.2 SOC 是什么，如何更新？
SOC 是 State of Charge，中文叫荷电状态，表示储能当前有多满。

| SOC  |   含义    |
| :--: | :-----: |
|  0   |  完全没电   |
| 0.25 | 剩余25%容量 |
| 0.5  | 剩余50%容量 |
|  1   |  完全充满   |
ASSUME 中：
- 充电功率是负数；
- 放电功率是正数。

假设充电功率为 P_t < 0，则：$SOC_{t+1} = SOC_t + (-P_t * Δt * η_c) / C$
其中：
- $P_t$：市场实际成交功率，充电时为负；
- $Δt$：时间长度；
- $η_c$：充电效率；
- $C$：储能容量。

假设放电功率为 $ $P_t$ > 0 $，则：
$$
SOC_{t+1} = SOC_t - \frac{P_t \Delta t}{\eta_d C}
$$
### 2.3.3 储能什么时候充电、什么时候放电
- 策略根据预测价格决定提交哪一种报价。
- 市场出清后，才决定是否真的充电或放电。

在 `storage_energy_heuristic_flexible` 中，默认计算当前时刻前后约 12 小时价格预测的平均值：$$\bar{p} = \operatorname{mean}(p_{t-12h},\ \ldots,\ p_t,\ \ldots,\ p_{t+12h})$$
$$p_t^{forecast} \quad \text{和} \quad \bar{p}$$
- 当前预测价格较高，SOC 允许放电，策略提交：
	- 正功率报价；
	- 作为供给方卖电；
	- 最大功率受到放电功率、SOC 和爬坡约束。

	放电报价：$$p_{\text{discharge}} = \frac{\bar{p}}{\eta_d}$$
- 当前预测价格较低，SOC 允许充电，策略提交：
	- 负功率报价；
	- 作为需求方购买电能充电；
	- 最大功率受到充电功率、SOC 和爬坡约束。

	充电报价：$$p_{\text{charge}} = \bar{p}\,\eta_c$$

|      市场价格 | 经济动作  |
| --------: | ----- |
|    不高于 43 | 适合充电  |
|  43～55.56 | 通常不动作 |
| 不低于 55.56 | 适合放电  |
预测价格选择报价方向→SOC确定可报数量→市场出清→成交后才真正更新SOC。
- `SOC = 0`：没有能量，不能放电；
- `SOC = 1`：已经充满，不能继续充电；
- `0 < SOC < 1`：可能充电或放电，但数量还受功率和爬坡限制。

|阶段|使用的量|作用|
|---|---|---|
|制定报价|可充/放功率、预测价格、当前 SOC|决定最多报多少|
|市场出清|`accepted_volume`|确定实际充电或放电量|
|状态更新|实际成交量|更新真实 SOC|
### 2.3.4 完整流程
- SOC 表示剩余电量比例；
- 预测电价决定想充电还是放电；
- 报价价格考虑充放电效率；
- 实际成交量决定 SOC 更新。

预测价格→生成储能报价→进入市场排序→确定出清价格→得到成交量→计算收益→更新SOC
## 2.4 powerplant_energy_heuristic_block
把火电机组“必须连续运行的最低出力”打包成一个跨时段的整体报价；额外的可调出力仍然逐小时报价。

出现这个算法的原因是 [[策略介绍 1#2.2 demand_energy_heuristic_elastic]] 主要解决火电机组不能随意“一小时开、一小时停”的问题。

块报价则可以表达：
> 我愿意在这三个小时里每小时至少发200 MW，但这三小时的最低出力必须整体接受；不能只接受其中一个小时。

### 2.4.1 生成两类报价
$$P_{t}^{\max}=P_{t}^{\mathrm{inflex}}+P_{t}^{\mathrm{flex}}$$

| 组成                        | 含义          | 报价形式        |
| ------------------------- | ----------- | ----------- |
| $P_{t}^{\mathrm{inflex}}$ | 机组最低稳定出力    | 多个小时合成一个块报价 |
| $P_{t}^{\mathrm{flex}}$   | 最低出力以上的额外能力 | 每小时一个普通报价   |
### 2.4.2 块报价的价格怎么得到？
程序先分别计算每小时的最低出力报价，然后求电量加权平均价：
$$
C^{\mathrm{block}}=\frac{\sum_{t\in\mathcal{T}} C_{t}^{\mathrm{inflex}} P_{t}^{\mathrm{inflex}}}{\sum_{t\in\mathcal{T}} P_{t}^{\mathrm{inflex}}}
$$其中的 $C^{\mathrm{block}}$ 为整个块只有一个报价价格，但是每个小时的电量可以不同。
同时 $C_{t}^{\mathrm{inflex}}$ 为 [[策略介绍 1#2.1.2 稳定出力怎么定价]]

minimum acceptance ratio，即最小接受比例。

## 2.5 powerplant_energy_heuristic_linked
最低稳定出力组成父块报价，逐小时灵活出力作为它的子报价；父块不成交，子报价绝对不能成交。

情况1
	父块：拒绝
	08:00子报价：必须拒绝
	09:00子报价：必须拒绝
	10:00子报价：必须拒绝
情况2
	父块：接受
	三个子报价：全部拒绝
情况3
	父 和 子 都成交。

### 2.5.1 父 和 子 报价块
{
    "bid_id": "Unit1_block",
    "price": 45,
    "volume": {
        "08:00": 200,
        "09:00": 200,

    },

{

## 2.6 powerplant_capacity_heuristic_balancing_pos/neg
`pos/neg` 不是让机组现在改变出力，而是让机组向备用市场承诺：“需要时，我可以增加或减少这么多功率。”
同一个策略类不会同时提交两个价格，而是根据 `market_config.product_type` 选择对应报价：

|产品类型|含义|报什么价格|
|---|---|---|
|`capacity_pos`|预留向上调节能力|正备用容量价格|
|`energy_pos`|实际调用向上调节|正备用能量价格|
|`capacity_neg`|预留向下调节能力|负备用容量价格|
|`energy_neg`|实际调用向下调节|负备用能量价格|
### 2.6.1 正备用表示和价格：
电力不足时，我还能向上增加多少出力。

例如机组最大 1000 MW，先只发 600 MW，预留 400 MW。这 400 MW 就是正备用容量。
问题来了：这 400 MW 如果提前卖进 EOM（按电量卖），高电价时本来能赚一笔。现在锁给备用，这笔钱没了。

源码先计算未来默认4小时的单位容量潜在收益：$$ R = \sum_{\tau=t}^{t+H} (\hat{p}_{\tau} - C^{\text{marginal}}), \quad H = 4\text{ h} $$当 $R \ge 0$ 时：
$$ p^{\text{capacity,pos}} = R $$
如果把1 MW容量留给备用市场，会损失40欧元的EOM利润，那么正备用容量至少也要报价40欧元。

当 R<0 时，说明预测电价低于边际成本，机组原本不值得发电。但为了保持正备用能力，机组可能需要维持最低出力，因此源码把这部分亏损分摊到备用容量上：$$ p^{\text{capacity,pos}} = |R| \frac{P_{\min}}{Q^{\text{pos}}} $$
### 2.6.2 负备用 balancing_neg
负备用表示：
> 电力过剩时，我可以向下减少多少出力。

机组愿意为“少发电”接受较低甚至负的调用价格，因为少发电本身能够节省40欧元成本。
如果 R<0，机组原本不愿运行，但为了提供“向下减发”能力，它必须先保持一定出力，所以需要容量补偿：
$$ p^{\text{capacity,neg}} = |R| \frac{Q^{\text{neg}} - P_{\min}}{Q^{\text{neg}}} $$
 第一步，代码认为需要补偿的出力是：
 $$ Q^{\text{neg}} - P_{\min} = 400 - 200 = 200 \text{ MW} $$
## 2.7 storage_capacity_heuristic_balancing_pos/neg
计算储能可以提供多少正备用，以及报什么价格。

正备用表示：电网缺电时，储能能够让自己的功率“向上增加”。

它有两种实现方式：
- 减少充电；
- 增加放电。

假设储能：
- 最大放电功率：100 MW；
- 当前正在充电：$P_{\mathrm{EOM}} = -40\ \mathrm{MW}$；
- SOC和爬坡能力都足够。

它接到正备用激活指令后，可以从：
$$
-40\ \mathrm{MW} \rightarrow +100\ \mathrm{MW}
$$
因此正备用容量是：
$$
Q^{pos} = 100 - (-40) = 140\ \mathrm{MW}
$$
这140 MW由两部分组成：
$$
\underbrace{40\ \mathrm{MW}}_{\text{停止充电}} + \underbrace{100\ \mathrm{MW}}_{\text{开始放电}} = 140\ \mathrm{MW}
$$

| 当前状态 |   当前功率 |   最大放电 |  正备用容量 |
| ---- | -----: | -----: | -----: |
| 正在充电 | −40 MW | 100 MW | 140 MW |
| 空闲   |   0 MW | 100 MW | 100 MW |
| 正在放电 |  60 MW | 100 MW |  40 MW |
$$
Q^{pos} = P_{\mathrm{max,feasible}} - P_{\mathrm{EOM}}
$$
$$
Q^{pos} = \min(\text{功率上限}、\text{SOC上限}、\text{爬坡上限}、\text{剩余容量})
$$
注意：

| 产品             | 含义        | 是否实际放电 | 是否改变SOC |
| -------------- | --------- | ------ | ------- |
| `capacity_pos` | 承诺保留正备用容量 | 否      | 否       |
| `energy_pos`   | 正备用被实际激活  | 是      | 是       |
EOM基准出力 → SOC与爬坡约束 → $Q^{pos}$ → 计算EOM机会成本 → 形成正备用报价

### 2.7.1 容量价格：只要待命就可以获得
储能向正备用市场申报：
- 正备用容量：100 MW；
- 容量价格：5 €/MW；
- 备用时段：08:00—12:00。
如果这笔容量报价成交，即使电网最终一次也没有调用储能，储能仍然可以获得容量收入。因为储能为了待命，可能放弃了在EOM中充放电套利的机会，所以需要获得补偿。

### 2.7.2 激活电价
假设电网在09:00突然缺电，要求储能：
- 增加放电30 MW；
- 持续30分钟；
- 激活电量价格：80 €/MWh。

| 情况            | 容量费 | 激活电量费    |
| ------------- | --- | -------- |
| 容量报价成交，但没有被调用 | 有   | 没有       |
| 容量报价成交，并且被调用  | 有   | 有        |
| 容量报价没有成交      | 没有  | 通常也不会被调用 |

| ASSUME产品       | 交易内容    | 报价含义            |
| -------------- | ------- | --------------- |
| `capacity_pos` | 正备用容量   | 为系统预留多少MW       |
| `energy_pos`   | 正备用激活电量 | 实际增加多少MWh       |
| `capacity_neg` | 负备用容量   | 为系统预留多少MW向下调节能力 |
| `energy_neg`   | 负备用激活电量 | 实际减少多少MWh       |
### 2.7.3 电网电力过剩时，储能降低对外供电
负备用可能要求储能充电，所以电池不能太满。
假设：
- 储能容量：400 MWh；
- 当前 $SOC = 0.70$；
- 最大 $SOC_{\max} = 0.90$；
- 充电效率：$\eta_c = 0.8$；
- 产品持续1小时。

剩余内部容量：
$$
(0.9 - 0.7) \times 400 = 80\ \mathrm{MWh}
$$
对应最多可以从电网吸收：
$$
E_{\mathrm{grid,max}} = \frac{80}{0.8} = 100\ \mathrm{MWh}
$$
所以1小时内最多充电：
$$
P_{\mathrm{SOC,max}} = 100\ \mathrm{MW}
$$
最终负备用容量需要同时受到以下条件限制：
$$
Q^{neg} = \min(\text{充电功率限制}、\text{SOC限制}、\text{爬坡限制}、\text{剩余市场容量})
$$
ASSUME源码也通过 $SOC_{\max}$、储能容量、充电效率和持续时间计算最大可充电功率。

电网电力过剩时，**储能愿意免费吸收电能**，因为这些电能储存后可能在未来出售。但是**火电是需要付费的。**
