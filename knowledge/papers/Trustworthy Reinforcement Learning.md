## 问题
当新能源基地与调度中心之间发生通信故障，调度中心只能看到“过时的系统状态”时，如何继续安全、经济地控制火电机组和储能系统。状态上传发生延迟，但控制指令仍能正常下发并按照预期执行。

## 系统中包含的部分
- 风力发电 WG：不可控制，风大就发得多；
- 光伏发电 PV：不可控制，阳光强就发得多；
- 火力发电 TPG：可以调节输出功率；
- 电池储能 BES：可以充电或放电；
- 主电网：新能源基地可以从电网买电，也可以向电网卖电；
- 负荷：用户需要消耗的电力。

风电、光伏和负荷会不断变化；真正可以被调度中心控制的是：
$$火电机组出力+储能充放电功率$$
## 调度中心做了什么
每隔一小时，调度中心会收到当前系统状态，例如：
- 当前风电、光伏发了多少电；
- 当前负荷需要多少电；
- 火电机组现在输出多少；
- 电池还剩多少电，即 SOC；
- 当前买电、卖电价格；
- 当前与主电网交换了多少电。

然后调度中心根据这些信息下达控制指令：
- 三台火电机组分别发多少电；
- 电池现在应该充电还是放电。

目标=满足用电需求 + 不违法设备约束 + 运行成本尽可能低

## 输入与输出

| 项目   | 内容                          |
| ---- | --------------------------- |
| 输入   | 延迟的系统状态、过去执行过的控制动作          |
| 输出   | 火电机组出力、储能充放电功率              |
| 优化目标 | 最小化火电成本和电网购电成本              |
| 必须满足 | 功率平衡、火电功率与爬坡约束、储能功率与 SOC 约束 |

论文虽然仍以 MDP 形式描述，但它提出状态估计模块，实际上就是在尝试：
延迟状态 + 历史动作 ⟶ 估计当前状态 ⟶ 进行调度

## 为什么不关注于模型的设计
需要区分监督学习中的训练和强化学习中的训练。

但这篇论文没有“正确调度动作”作为标签。没有数据告诉模型：
> 在这个状态下，三台火电机组和储能分别应该输出多少功率。

所以它只能让智能体与仿真环境反复交互，通过运行成本判断动作好不好。这时：
> 强化学习算法、奖励设计和探索方式，本身就是训练机制。

## 模型应该学习什么
如果奖励只写成“降低运行成本”，模型可能通过违反设备约束来获得低成本，例如：
- 让电池无限放电；
- 让火电机组瞬间提高几百 MW；
- 让 SOC 低于零。
模型结构再先进，也只会更高效地学习这个错误目标。

## 模型如何获得训练数据
监督学习的数据集是提前固定的。
强化学习的数据由策略自己产生：
>当前策略→选择动作→进入新状态→产生下一批训练数据

如果探索不好，智能体根本看不到有价值的状态。奖励设计会直接影响它去哪里收集训练数据。

## 如何保证动作安全
普通神经网络只能输出一个数值，并不知道：
- 火电机组最大出力是多少；
- 爬坡速度能有多快；
- 电池 SOC 是否即将越界。
因此安全约束不能只依赖模型结构，需要通过约束优化、安全投影或者安全强化学习处理。

## 存在的问题（不确定）
特别是通信故障后，最核心的问题其实是：
如何根据历史状态和动作，准确预测当前真实状态？

论文使用了一个 GLU＋Transformer，但：
- 没有与 MLP、LSTM、GRU、Kalman Filter 对比；
- 没有系统研究输入多长的历史序列最好；
- 没有报告每个状态变量的预测误差；
- 没有输出预测不确定性；
- 只输入一个延迟状态和历史动作，难以预测突发的风电、光伏和负荷变化。

也就是说，论文在 SDRS 奖励塑形上设计得比较复杂，但作为前提的“当前状态到底估计得准不准”，反而验证得不充分。

# 问题重新思考
拆解成两个问题 = 看不清当前状态 + 知道后如何控制。
## 看不清当前状态
通信故障后，调度中心只能收到旧状态：$s_{t-d}$
第一部分根据历史状态和动作预测当前状态：
$$(s_{t-d}, a_{t-d}, \dots, a_{t-1}) \rightarrow \hat{s}_t$$
这部分比较容易训练，因为仿真的真实状态是已知的，属于监督学习：
$$\mathcal{L}_{\text{state}} = \|\hat{s}_t - s_t\|^2$$
这样我们可以明确判断：模型到底有没有把当前状态预测准确。
## 知道如何控制
拿到预测状态后，再决定：$\hat{s}_t \rightarrow a_t$
输出火电机组和储能的控制动作，同时满足：
- 功率供需平衡
- 火电最大、最小出力
- 火电爬坡约束
- 储能功率约束
- SOC约束

这一部分可以使用 PPO，也可以使用 MPC、数学规划或约束强化学习。
## 不设计一个端到端的 PPO
直接设计一个：
$$(s_{t-d}, a_{t-d:t-1}) \rightarrow \text{神经网络} \rightarrow a_t$$
1. 训练信号太间接。PPO最后只知道“运行成本高不高”，却不知道成本高到底是因为：
	- 光伏预测错了；
	- 负荷预测错了；
	- SOC估计错了；
	- 还是调度策略本身错了。
2. 状态估计训练不充分。监督学习中每个时刻都有真实状态作为标签，而 PPO 只能通过长期累计奖励反向学习，信号弱得多。
3. 安全性难解释。一个端到端网络直接输出动作，我们很难说明它为什么不会违反 SOC 或火电约束。
4. 无法定位错误。拆开以后：
	- 如果 $\hat{s}_t$ 不准确，就是状态估计模块的问题；
	- 如果 $\hat{s}_t$ 很准确但调度成本很高，就是控制策略的问题；
	- 如果动作越界，就是安全控制层的问题。
